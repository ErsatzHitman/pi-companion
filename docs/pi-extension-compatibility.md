### 9.4 `compaction_end`'s discarded payload

`PiAgentSessionEvent`'s `compaction_end` arm types its payload as `result?: unknown`. The

```ts
interface CompactionDetails {
  readFiles: string[];
  modifiedFiles: string[];
}
interface CompactionResult<T = unknown> {
  summary: string;
  firstKeptEntryId: string;
  tokensBefore: number;
  estimatedTokensAfter?: number;
  usage?: Usage;
  details?: T; // T = CompactionDetails in the ordinary compaction path
}
```

So Pi's structured `summary`, `firstKeptEntryId`, `tokensBefore`, `estimatedTokensAfter`,
`usage`, and `details.{readFiles, modifiedFiles}` are all discarded at the `result?: unknown`
boundary — none of it reaches `agent.ts`'s `case "compaction_end"` handler (which never reads
`event.result` at all), `packages/protocol/src/agent-types.ts`'s `CompactionTimelineItem`
(which has no `summary`/`details` field to carry it even if the daemon read it), or
`packages/frontend-core`'s `transcript-view.ts` (which forwards only `status`, `trigger` and
`preTokens`). T38B3 (`apps/web/src/features/transcript/compaction-row.tsx`) found and disclosed
this in full — including the exact three-step fix (this file's `rpc-types.ts`, then
`agent-types.ts`, then `transcript-view.ts`) — and rendered an honest "not available" message
rather than a placeholder implying completeness, explicitly filing the daemon-side step for
"whoever picks up T51A's mirror audit."

`rpc-types.ts` (this task's owned file) without also touching
`packages/protocol/src/agent-types.ts` and `packages/frontend-core/src/timeline/transcript-view.ts`
(both outside this task's Owns grant and both other tasks' territory) would produce exactly the
"half a mount" this repository's own history warns against — a stronger daemon-side type that
